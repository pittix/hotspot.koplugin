[SIZE=4][B]hotspot.koplugin: your e-reader as a Wi-Fi access point[/B][/SIZE]

Hi all,

[B]hotspot.koplugin[/B] is a small KOReader plugin that makes the e-reader broadcast its own Wi-Fi network: hostapd runs the access point, BusyBox udhcpd hands out addresses. It does [I]not[/I] share an internet connection. The point is to connect a phone, a laptop or another stock ereader [I]directly[/I] to the reader when there's no router around and move books over that link.

The plugin was written by [B]Ying Stokes[/B] ([URL=https://github.com/thorondir/hotspot.koplugin]thorondir/hotspot.koplugin[/URL]) for the Kobo Clara 2E. [URL=https://github.com/pittix/hotspot.koplugin]My fork[/URL] adds the MediaTek Kobos and a research report on other brands. 
This thread is about going further, and I can't do that by myself: I already extended the code for my Kobo Libra Colour, but that's it.

[SIZE=3][B]What it does[/B][/SIZE]
[LIST]
[*]Broadcasts an AP with configurable SSID, channel and optional WPA2 password
[*]The reader gets 192.168.42.1, clients get DHCP leases in 192.168.42.10-100
[*]Menu: [I]Settings -> Network -> Wi-Fi hotspot[/I] (can also start automatically with KOReader)
[*]Built for 1-2 clients at a time
[/LIST]

My idea was to pair it with [B]filesync.koplugin[/B] by [B]abrahamnm[/B] ([URL=https://github.com/abrahamnm/filesync.koplugin]abrahamnm/filesync.koplugin[/URL]), or any quick-share alternative that may require a wifi connection.
In my case, the workflow to share the ebooks from my device is that another device joins the reader's hotspot, open filesync URL in their browser, browse and download books. 
I'm also working on a plain, e-ink-friendly filesync page so that [I]another e-reader's[/I] browser can use it. That's only a branch on my fork for now ([URL=https://github.com/pittix/filesync.koplugin/tree/feat/eink-mode]feat/eink-mode[/URL]), and the upstream PR is still to come. Hotspot + filesync together hasn't been tested end to end on more devices yet, so reports on that are welcome too.

[SIZE=3][B]Current status[/B][/SIZE]
[LIST]
[*][B]Kobo Clara 2E[/B] (Marvell/NXP moal, AP on uap0): tested
[*][B]Kobo Libra Colour[/B] (MediaTek wlan_drv_gen4m, AP on ap0): tested (FW 4.46.23836, KOReader v2026.07.2)
[*][B]Kobo Clara BW / Clara Colour[/B]: [B]untested[/B], same MediaTek driver as the Libra Colour, so it should work
[*][B]Other Kobos[/B]: the plugin says the Wi-Fi chip isn't supported yet. Tell me your WIFI_MODULE (see below)
[*][B]Kindle, PocketBook, reMarkable, others[/B]: not supported yet. A desk-research report covers which ones look feasible: [URL=https://github.com/pittix/hotspot.koplugin/blob/other-models/docs/other-ereaders-report.md]report[/URL]
[/LIST]

[SIZE=3][B]What the research says about other devices[/B][/SIZE]
Short version. Details and every source are in the report.
[LIST]
[*][B]Kindle with MediaTek Wi-Fi[/B] (PW5/PW5 SE, Basic 2022/2024, PW6, Scribe 1/2, Colorsoft): [B]most promising[/B]. A MediaTek Kindle dump shows the same Wi-Fi modules as the Libra Colour (wmt_drv / wmt_chrdev_wifi / wlan_drv_gen4m), kernel 4.9, and KOReader runs as root there. What's missing is Kindle glue: take Wi-Fi over from Amazon's wifid, open the firewall, keep the screensaver off.
[*][B]Kindle Voyage[/B] (Atheros AR6003): [B]already done by someone else![/B] [B]unrealJune[/B]'s kindshare runs hostapd + busybox udhcpd as a SoftAP on a Voyage (FW 5.13.6) with the stock ath6kl driver. See the credits below.
[*][B]Kindle PW2 / PW3 / Basic 7th[/B] (Atheros): depends on whether your firmware loads ath6kl (like the Voyage) or Amazon's older ar6003/ar6000 driver. One lsmod line tells us which.
[*][B]Kindle Basic 8th gen, PW4, Basic 10th, Oasis 2/3[/B] (Broadcom BCM4343W): likely. The Basic 8th gen uses bcmdhd with cfg80211, the usual AP setup for that chip. The others are probably the same, unconfirmed.
[*][B]PocketBook B288 devices[/B] (Touch Lux 4/5, InkPad 3, Touch HD 3, Color, InkPad X, ...): likely [B]if rooted[/B]. PocketBook's published kernel has cfg80211/mac80211 and an XRadio driver that should be able to do AP. Without root, KOReader can't start hostapd.
[*][B]PocketBook B300[/B] (newest models): unknown, the Wi-Fi driver hasn't been identified.
[*][B]reMarkable 1/2[/B]: likely (brcmfmac, root over SSH).
[*][B]Cervantes, Bookeen, older Kindles/PocketBooks, Sony PRS-T[/B]: possible with a lot of work, or unlikely.
[*][B]Android readers (Boox etc.)[/B]: out of scope, they already have a system hotspot.
[/LIST]
Nothing outside Kobo has been tried on a device yet, and that's where you may come in.

[SIZE=3][B]How you can help[/B][/SIZE]

[B]1. Kobo owners: try it[/B]
Especially Clara BW, Clara Colour, and Tolinos running the Kobo build of KOReader on MediaTek hardware.
[LIST=1]
[*]Download the [URL=https://github.com/pittix/hotspot.koplugin/archive/refs/heads/main.zip]main branch zip[/URL], rename the extracted folder to [B]hotspot.koplugin[/B], copy it to [I].adds/koreader/plugins/[/I]
[*]Restart KOReader, open [I]Settings -> Network -> Wi-Fi hotspot[/I], set a password, enable it
[*]Join from your phone, check you get a 192.168.42.x address, then try filesync or SSH on 192.168.42.1
[*]Post your model, firmware, KOReader version, whether it worked, and any message the plugin showed. Feel free to commit to the github repo as well :D
[/LIST]
On MediaTek Kobos the chip can't be a client and an AP at the same time, so the plugin turns normal Wi-Fi off first (it asks before doing so). Keep the reader awake while you use it: KOReader turns Wi-Fi off on sleep, and that stops the hotspot too.
If your Kobo says "not supported", post the output of [I]echo $WIFI_MODULE[/I] (from KOReader's terminal) together with the check in step 2.

[B]2. Everyone else (Kindle, PocketBook, reMarkable, Cervantes, Bookeen, unsupported Kobos): run a read-only check[/B]
These commands only read information; they change nothing. Run them as root (KOReader's terminal or SSH; on a rooted PocketBook, through su) and paste the output inside CODE tags (the # button in the editor).
[CODE]
uname -a
grep -E 'Hardware|Features' /proc/cpuinfo
lsmod
ls /sys/class/net/ /sys/class/ieee80211/
for d in /sys/class/net/*/device/driver; do echo "$d -> $(readlink -f $d)"; done
zcat /proc/config.gz 2>/dev/null | grep -E 'CFG80211|NL80211|WIRELESS_EXT|NETFILTER'
for b in iw ip ifconfig iwconfig hostapd udhcpd iptables busybox; do printf '%s: ' $b; which $b || echo missing; done
iw list 2>/dev/null | sed -n '/Supported interface modes/,/Supported commands/p'
iw list 2>/dev/null | grep -A6 'interface combinations'
[/CODE]
Extra lines for some platforms:
[CODE]
# Kindle (any model)
status wifid; status wmt; ls -l /dev/wmtWifi 2>/dev/null; iptables-save
# Kindle with Broadcom (Basic 8th/10th, PW4, Oasis)
for p in /sys/module/*dhd*/parameters/*; do echo "$p: $(cat $p)"; done
# PocketBook
id; ls -l /mnt/secure/su; ps | grep -Ei '[n]etagent|[w]pa_'
[/CODE]
Please remove anything personal before posting (MAC addresses, network names, serial numbers). These commands shouldn't print any, but check anyway.

[B]3. MediaTek Kindle owners who want to go one step further (optional, at your own risk)[/B]
This single test would tell us whether the Kindle port can reuse the Libra Colour code. It switches the Wi-Fi chip to AP mode the way the plugin does on Kobo, and checks whether an [I]ap0[/I] interface appears. Wi-Fi is off during the test. On Kobo, doing this while MediaTek's firmware daemons aren't running reboots the device, so the first line checks for them. If it prints nothing, stop there.
[CODE]
ps | grep -i '[w]mt'      # expect wmt_launcher / wmt_loader; stop here if empty
lipc-set-prop com.lab126.cmd wirelessEnable 0; sleep 3; stop wifid
echo A > /dev/wmtWifi; sleep 3; ls /sys/class/net; dmesg | tail -40
# restore
echo 0 > /dev/wmtWifi; start wifid; lipc-set-prop com.lab126.cmd wirelessEnable 1
[/CODE]
